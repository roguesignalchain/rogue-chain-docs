# 桌面客户端配置与保险库安全

本指南详细说明 **Rogue Desktop Client** 中 **Settings** 标签页的每一项配置、这些配置如何映射到底层 `core-rogue` 守护进程，以及私钥在磁盘上的加密保护机制。

---

## ⚙️ 设置参考

### 1. 本地节点管理器设置

这些参数控制由桌面客户端管理的内置 `core-rogue` 边车进程。修改后将在下次停止并重新启动节点时生效。

| 设置项 | 默认值 | 对应 CLI 参数 | 说明与建议 |
| :--- | :--- | :--- | :--- |
| **P2P 端口** | `38888` | `--port` | 用于发现对等节点及广播区块/交易的 TCP/UDP 端口。在路由器或防火墙上转发此端口可获得更好的节点连接性。 |
| **HTTP RPC 端口** | `38845` | `--http.port` | `core-rogue` 提供 JSON-RPC 2.0 服务的本地端口（`127.0.0.1`）。界面提供快捷同步按钮，可自动将 **RPC Endpoint URL** 更新为匹配该端口。 |
| **WebSocket 端口** | `0`（禁用） | `--ws.port` | 默认设为 `0` 以避免本地已有其他节点运行时发生端口冲突。设置为 `38846`（或其它不与 HTTP 端口冲突的空闲端口）即可启用 `--ws` 订阅。 |
| **数据目录（`datadir`）** | 系统应用数据目录 / `./nodes-local/node-desktop`（开发模式） | `--datadir` | 存储 `geth/chaindata`（区块链状态与区块）的文件系统路径。随着链数据增长，需要 100–200+ GB 的可用 SSD/NVMe 空间。 |
| **引导节点（Bootnodes）** | Rogue Signal 默认种子 `enode://...` | `--bootnodes` | 以逗号分隔的 `enode://<pubkey>@<ip>:<port>` 地址列表，用于启动时引导 P2P 节点发现。留空则会回退至 `ROGUE_BOOTNODES` 环境变量或内置网络默认值。 |
| **数据库缓存（MB）** | `256` | `--cache` | 分配给 LevelDB 与状态树缓存的内存大小（MiB）。点击设置中的 **Check System Resources** 可自动检测 CPU 核心数与可用内存并应用推荐缓存大小。 |
| **同步模式（Sync Mode）** | `full` | `--syncmode` | **强制完整验证**（`full`）。即使界面中选择了 `snap`，桌面客户端的进程管理器也会强制传入 `--syncmode full`，以确保完整的 RandomX PoW 校验并避免 snap-sync 状态损坏。 |
| **日志详细级别（Verbosity）** | `3`（Info） | `--verbosity` | 控制输出到 **Node Console** 的 `core-rogue` 日志级别：`0`（静默）、`1`（错误）、`2`（警告）、`3`（信息）、`4`（调试）、`5`（详细追踪）。 |

:::tip 恢复默认设置
你可以随时在 Settings 中点击 **Reset Defaults**，一键恢复 Rogue Signal 标准端口（HTTP `38845`、WS `38846`、P2P `38888`）、`256 MB` 缓存、`full` 同步模式、日志级别 `3` 以及 `15` 分钟自动锁定。
:::

### 2. RPC 与应用安全设置

| 设置项 | 默认值 | 说明与建议 |
| :--- | :--- | :--- |
| **RPC 端点 URL** | `http://127.0.0.1:38845` | Wallet、Dashboard、Mining 和 Explorer 视图使用的 JSON-RPC 地址。使用本地节点时指向 `http://127.0.0.1:<port>`；若不想运行本地节点，也可填入远程/VPS 节点地址（例如经由 HTTPS 代理的端点）。 |
| **自动锁定计时器（分钟）** | `15` | 在无操作 `N` 分钟后自动锁定内存中已解密的钱包。在共享设备或便携笔记本上建议设置更短的间隔（例如 `5` 分钟）。 |

### 3. 节点控制与数据库维护（危险区）

在 Settings 顶部，你可以手动点击 **Start Node** 或 **Stop Node**，无需重启桌面客户端。

在 Settings 底部的 **Danger Zone** 中提供 **Clean Chaindata** 功能：
* **功能说明：** 停止受管的 `core-rogue` 进程（若正在运行），并删除你配置的 `datadir` 下的 `geth/chaindata` 目录。下次启动时，节点将重新初始化第 0 区块并从头同步区块链。
* **适用场景：** 仅在因意外断电导致本地链数据库损坏，或切换不兼容的本地测试网时使用。
* **绝不会触碰的内容：** **Clean Chaindata 绝不会删除你的 `.rogue-wallet.vault` 或私钥。** 你的资金与钱包将完全保持安全。

## 🔐 保险库安全与加密架构

你在 `ROGUE` 网络上的资产安全取决于私钥的机密性与完整性。桌面客户端采用严格的自托管、零知识本地保险库架构：

1. **CSPRNG BIP-39 助记词生成：**
   * 新建钱包使用操作系统提供的密码学安全伪随机数生成器生成 12 词（128 位熵）或 24 词（256 位熵）英文 BIP-39 助记词。
   * 账户通过 **HMAC-SHA512** 沿标准 EVM BIP-44 路径确定性派生：`m/44'/60'/0'/0/0`（更多账户依次为 `.../1`、`.../2` 等）。

2. **Argon2id + AES-256-GCM 磁盘加密：**
   * 所有钱包、标签和助记词均本地保存在 `.rogue-wallet.vault` 文件中。
   * 主密码永远不会写入磁盘，而是与 16 字节随机盐值结合，经过 **Argon2id**（一种抗 GPU/ASIC 暴力破解的内存硬密钥派生函数）拉伸派生出 256 位加密密钥。
   * 保险库数据使用 **AES-256-GCM** 配合唯一随机 nonce 进行加密和认证，同时保护机密性与防篡改完整性。

3. **仅限内存签名：**
   * 交易仅在 Rust 后端内存中（`secp256k1`）完成签名，并以已签名的 Legacy（`Type 0`）十六进制载荷形式发送给节点。私钥永远不会暴露给 RPC 端点或网络节点。

## ⚠️ 安全备份最佳实践

> [!CAUTION]
> 切勿将 12 词或 24 词助记词以明文形式保存在电子邮件、云盘、截图或聊天软件中。任何获取你助记词的人都可以立即且不可逆地控制所有派生账户及资金。

* **物理离线备份：** 将助记词抄写在纸上或刻录在防火金属备份板上，并存放在安全的物理位置。
* **大额转账前验证恢复：** 创建钱包后，在转入大额 `ROGUE` 资产前，务必核对每个单词的拼写与顺序完全准确。
* **高强度主密码：** 为 `.rogue-wallet.vault` 设置独立的高熵主密码，即使本地磁盘备份意外泄露，Argon2id + AES-256-GCM 加密也无法被暴力破解。
* **备份保险库文件（可选）：** 只要牢记主密码，你也可以将 `.rogue-wallet.vault` 与物理助记词备份一同妥善保存。
